# /invent 실행 절차

입력: `$ARGUMENTS` (질문 또는 아이디어). 비어 있으면 대표님께 무엇을 조사할지 한 줄로 물어본다.

## 0. 준비

1. 오늘 날짜와 주제로 폴더를 만든다: `runs/YYYY-MM-DD-<주제 짧은 영문 슬러그>/`
2. 그 폴더에 `00-질문.md`를 쓴다: 원래 질문, 총괄이 해석한 질문, 1단계부터인지 2단계부터인지.
3. 판단 기준: 입력이 "어떤 제품을 만들까"류(영역만 있음)면 1단계부터. 입력이 구체적 제품·기능이면 2단계부터.
4. `sources/출처안내서.md`와 `rubric/점수표.md`를 읽는다.

## 1단계. 탐색 (넓은 질문일 때만)

1. 영역 분할: 주제를 생활 장면 기준으로 5~8개 영역으로 쪼갠다. 예) 욕실 → 샤워, 세면·양치, 수납, 청소·곰팡이, 노인·안전, 아동, 환기·습기, 배수.
   `01-영역.md`에 영역 목록과 쪼갠 이유를 쓴다.
2. 불편 발굴 담당(`pain-finder`)을 **영역마다 하나씩, 동시에** 띄운다. 각 호출에 넘길 것: 영역 이름, 주제, 저장 경로(`01-불편-<영역>.md`), 1단계 상한(웹검색 10회, Aside 금지).
3. 결과를 모아 `rubric/점수표.md`의 1단계 점수를 매긴다. 각 불편마다 빈도·강도·기존 해법 부족·제작 가능성을 1~5로 매기고 근거 등급을 붙인다. 점수가 같으면 근거 등급이 높은 쪽이 위.
   `02-점수표.md`에 전체 순위표를 쓴다.
4. 상위 3개 후보를 뽑아 대표님께 보여준다. 형식:
   - 후보 이름 한 줄, 누구의 어떤 불편인지, 점수, 근거 등급, 왜 1위인지(또는 왜 밀렸는지) 두 줄.
   - "하나를 고르시거나 '전부'라고 하시면 심층으로 갑니다."
5. **여기서 멈추고 답을 기다린다.** 답 없이 2단계로 넘어가지 않는다.

## 2단계. 심층 (후보마다)

후보 하나당 아래 순서. "전부"면 후보 세 개를 차례로.

1. 기존 해법 조사(`solution-scout`)와 왜 지금(`why-now`)을 **동시에** 띄운다. 넘길 것: 후보 설명, 대상 불편, 저장 경로(`10-기존해법.md`, `11-왜지금.md`), 2단계 상한.
2. 두 결과를 읽고, 각 결과의 "추가 조사 요청" 블록을 본다. 요청이 있으면 `source-digger`를 요청당 하나씩 띄운다(후보당 최대 4회). 결과는 `12-보조-<출처>.md`에 저장시키고, 해당 담당 결과 파일 끝에 "보조 조사 반영" 절을 총괄이 덧붙인다.
3. 디자인 제안(`design-proposer`)과 구현·원가(`build-cost`)를 **동시에** 띄운다. 넘길 것: 후보 설명, 불편 결과, 기존 해법 결과 경로(차별점을 알아야 함), 저장 경로(`20-디자인.md`, `21-구현원가.md`).
4. 검증(`verifier`)을 띄운다. 넘길 것: 이 후보 폴더의 모든 결과 파일 경로. 저장 경로 `30-검증.md`. 검증은 먼저 `tools/출처확인.py`를 돌려 `29-출처확인.md`를 만들고(URL 열림 여부·특허번호 대조·인용 대조), 그 위에서 주장별 판정을 한다. 검증이 "근거 불충분"으로 표시한 주장은 최종 보고서에서 등급을 내리거나 뺀다.
5. `templates/최종보고서.md` 양식대로 `40-최종보고서.md`를 쓴다. 모든 항목에 근거 등급을 붙인다. "검증해야 할 것" 절은 가정표(가치/사용/사업/구현 × 중요도 × 근거)로 반드시 채운다.

## 3. 전달

대표님께 최종 보고서 경로와 아래 요약을 준다:
- 한 줄 결론 (누구의 어떤 불편을 무엇으로 해결, 왜 지금)
- 가장 큰 위험 하나
- 다음에 사람이 직접 확인해야 할 것 3개
- 상한에 걸려 못 한 조사가 있으면 그 목록

## 상한과 중단

- 상한은 `CLAUDE.md`의 숫자를 따른다. 담당에게 넘길 때 숫자를 명시한다.
- 담당이 로그인 화면·캡차·접근 차단을 보고하면 그 출처는 건너뛰고 "미확인"으로 두고 진행한다. 대표님께는 전달 시점에 한 번에 알린다.
- Aside MCP 도구가 안 보이면(설치 안 됨) Aside 경유 출처는 전부 건너뛰고 전달 시점에 알린다.
- KIPRIS MCP 도구(`mcp__kipris__*`)가 안 보이거나 키 오류를 내면 기존 해법 담당은 Google Patents만 쓰고, 전달 시점에 "KIPRIS MCP 미설정"을 알린다.
- 1단계 결과 파일에서도 등급 기준은 `rubric/점수표.md` 하나다. 담당이 다른 기준을 적어 왔으면 총괄이 점수표를 매길 때 다시 센다.
