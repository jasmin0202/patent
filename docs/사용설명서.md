# 발명 조사 시스템 사용설명서

대표님용. 이 폴더(`D:\patent`)를 Claude Code로 열고 한 줄을 치면 담당 에이전트 9개가 조사해서 출처와 등급이 붙은 보고서를 만듭니다. 이 문서는 "무엇을 치면 무엇이 나오고, 막히면 어떻게 하는지"만 적었습니다. 설계 설명은 `README.md`, 규칙은 `CLAUDE.md`에 있습니다. (갱신 2026-10-29, 실용 모드 기본)

---

## 1. 이 앱이 하는 일

**우리 같은 소규모 회사가 만들어 팔 수 있는 일상·실용 제품**을 찾는 도구입니다. 욕실·주방·정리수납·시니어·반려동물·휴대용 소형 기기처럼 금형 한두 개와 KC 인증 한 종으로 끝나는 물건이 대상이고, 보고서는 "사람들이 무엇을 불편해하나 → 지금 팔리는 제품은 왜 부족한가(리뷰·가격) → 우리가 얼마에, 몇 개부터 만들 수 있나"로 답합니다. 특허는 "같은 물건의 등록 특허가 살아 있는가, 그 출원인이 제품을 파는가"까지만 봅니다. 그 이상의 특허 분석은 우리가 할 영역이 아니라서 따로 켜야 합니다.

출발점이 두 가지, 모드가 두 가지입니다.

| 명령 | 출발점 | 흐름 | 끝 |
|---|---|---|---|
| `/invent <질문 또는 아이디어>` | 사람의 불편 (**실용 모드**, 기본) | 불편 발굴 → (후보 선택) → 기존 해법(리뷰·가격대·특허 간단 확인)·왜 지금 → 디자인·구현원가(소규모 제작 세 숫자) → 검증 | `40-최종보고서.md` (진행 / 조건부 진행 / 지금은 아님) |
| `/invent --특허 <질문>` | 사람의 불편 (**특허 모드**) | 위와 같되 특허 조사를 깊게(KIPRIS 20회, 청구항 비교) | 같음 |
| `/discover <제품 또는 설명>` | 특허 지도 (항상 특허 모드) | 특허 지도 → 제품 대조 → 발상(제안 3개) → 검증 | `70-제안서.md` (제안 3개, 전부 "미확인(발상)") → 하나를 고르면 /invent 2단계로 |

모든 숫자와 주장에는 출처와 등급(확인됨 / 추정 / 미확인)이 붙고, 못 찾은 것은 못 찾았다고 씁니다. 특허 겹침 판단은 모드와 상관없이 "문언 수준, 법적 판단 아님"입니다.

## 2. 시작 전 준비

| 준비물 | 필수 | 없으면 |
|---|---|---|
| Claude Code로 `D:\patent` 열기 | 필수 | 아무것도 안 됨 |
| KIPRIS API 키 (환경변수 `KIPRIS_API_KEY`) | 권장 | 한국 특허 "간단 확인"을 Google Patents로만 하고 청구항 원문을 못 받음. 보고서에 "KIPRIS MCP 미설정" |

그게 전부입니다. 리뷰·가격·단가는 로그인 없이 열리는 곳(네이버쇼핑·다나와·알리익스프레스·앱 리뷰·Kicktraq·검색 스니펫)에서 봅니다. 쿠팡·아마존·알리바바 원문은 봇 차단으로 안 열리므로 검색 요약만 쓰고 보고서에 "(원문 미열람)"으로 표시됩니다. 로그인 브라우저(Aside)는 기본적으로 쓰지 않습니다. 꼭 쿠팡·알리바바 원문이 필요한 조사만 `/invent` 뒤에 "Aside 사용"이라고 적어 주시면 그 실행에서만 씁니다. 설치 방법은 `README.md` "설치" 절.

## 3. 명령 치는 법

**넓은 질문** — 탐색부터 시작합니다. 영역을 5~8개로 쪼개 불편을 모으고 점수표로 후보 3개를 보여 드립니다. 일상 제품은 이렇게 넓게 던지시는 게 좋습니다.

```
/invent 욕실용품에서 가장 필요한 발명품을 고안해줘
```

```
/invent 혼자 사는 70대 부모님 집에 두면 좋은 작은 생활용품
```

```
/invent 주방 서랍 정리에서 사람들이 제일 짜증내는 것
```

**구체적 아이디어** — 탐색을 건너뛰고 심층으로 갑니다.

```
/invent 휴대폰 뒷면에 붙이는 블루투스 스크롤 패드
```

```
/invent 세면대 배수구 머리카락 거름망인데 꺼낼 때 손에 안 닿는 것
```

**특허를 깊게 보고 싶을 때** — `--특허`를 붙이면 기존 해법 담당이 KIPRIS 20회·청구항 비교까지 합니다. 기본(실용) 모드는 "같은 물건 등록 특허가 살아 있나, 출원인이 제품을 파나"만 봅니다.

```
/invent --특허 휴대폰 뒷면에 붙이는 블루투스 스크롤 패드
```

**특허에서 거꾸로** — 같은 일을 하는 특허를 모아 지도를 그리고(살아 있는 벽·소멸한 아이디어 창고·거절 이유), 그 특허가 제품이 됐는지 대조한 뒤, 발상 담당이 빈 칸에서 제안 3개를 냅니다.

```
/discover 폰 뒷면에 붙여서 검지로 톡 치면 스크롤되는 블루투스 버튼
```

**쿠팡·알리바바 원문까지 보고 싶을 때** — 명령 뒤에 "Aside 사용"을 붙입니다. 안 붙이면 로그인 없이 열리는 곳만 씁니다.

```
/invent 세면대 배수구 머리카락 거름망 — Aside 사용
```

그 다음은 가만히 두시면 됩니다. 총괄이 담당을 띄우고 결과를 파일로 저장합니다. "실용 모드로 할까요?" 같은 질문은 하지 않습니다. 모드는 명령에 `--특허`가 있는지로만 정해집니다.

## 4. 대표님이 답하실 지점

| 명령 | 시점 | 총괄이 묻는 것 | 답 예 |
|---|---|---|---|
| /invent | 탐색 끝 | 후보 3개와 점수표 → "하나를 고르시거나 '전부'" | `2번`, `전부`, `A랑 C` |
| /invent | 심층 끝 | 보고서 경로, 한 줄 결론, 가장 큰 위험, 사람이 확인할 것 3개 | 읽고 다음 지시 |
| /discover | 제안서 끝 | 제안 3개 각 두 줄 → "하나를 고르시면 /invent 2단계로" | `제안 2로 가` |

그 외에는 혼자 진행합니다. 로그인·캡차·접근 차단을 만나면 우회하지 않고 멈춰서 "막힌 출처"에 적고, 전달 때 한 번에 알립니다.

소요 시간 감: 탐색 20~30분, 후보 하나 심층 30~60분, /discover 40~60분. 사용량 한도에 걸리면 멈췄다가 풀린 뒤 "다시 열었어"로 이어집니다.

## 5. 담당 9개가 하는 일

| 담당 | 답하는 질문 | 내놓는 파일 |
|---|---|---|
| 총괄 (이 대화) | 무엇을 조사할지, 어떤 후보가 이기는지 | 점수표, 보조 반영, 단면도, 최종 보고서·제안서 |
| 불편 발굴 | 사람들이 실제로 무엇을 불편해하는가 | `01-불편-<영역>.md` |
| 기존 해법 조사 | 지금 팔리는 제품은 왜 부족한가 — 리뷰 출처 2곳 이상, 리뷰 많은 상위 제품의 공통 불만 3가지, 가격대 구간표(1만/3만/5만 원+), 판매량 대리 지표(리뷰 수·랭킹), 특허 간단 확인(실용) 또는 청구항 비교(--특허) | `10-기존해법.md` / (discover) `51-제품대조.md` |
| 왜 지금 | 무엇이 달라져서 지금 가능한가 | `11-왜지금.md` |
| 보조 조사원 | 한 출처에서 한 질문만. 로그인 사이트는 "Aside 사용" 실행에서만 | `12-보조-<출처>.md` |
| 디자인 제안 | 기능 3개와 외형은 무엇인가 | `20-디자인.md` |
| 구현·원가 | 만들 수 있는가, 얼마에 — 부품표에 더해 **소규모 제작 세 숫자**(금형·초기비 합계 / 현실적 최소 주문량 / 인증 종류·비용·기간)와 신호등 | `21-구현원가.md` |
| 검증 | 각 주장을 출처가 뒷받침하는가 | `29-출처확인.md`, `30-검증.md` |
| 특허 지도 (discover) | 어떤 특허가 살아 있고 소멸했으며 무엇을 풀고 못 풀었나 | `50-특허지도.md`, `52-청구항.md` |
| 발상 (discover) | 빈 칸에서 어떤 제품이 가능한가 — 조사 없이 제안 3개 | `60-제안.md` |

조사하지 않는 담당이 셋입니다. 디자인은 받은 결과로 설계만, 검증은 적힌 출처를 다시 열기만, 발상은 받은 파일만 읽고 제안합니다. 검증은 등급을 내릴 수만 있고 올리지 못합니다.

## 6. 결과 읽는 법

결과는 `runs/<날짜>-<주제>/`에 쌓입니다. 파일 앞 숫자가 단계입니다.

```
runs/2026-10-23-bathroom/              ← /invent (넓은 질문)
  00-질문.md        해석·시작 단계·상한·재개 기록
  01-영역.md, 01-불편-<영역>.md ×N, 02-점수표.md
  50-종합요약.md    후보 3개 결론 한눈에  ← 먼저 여기
  A-<후보>/ 10-기존해법 11-왜지금 12-보조-* 20-디자인 21-구현원가 22-단면도.svg 29-출처확인 30-검증 40-최종보고서

runs/2026-10-24-toktok-scroll-pad/     ← /invent (구체적 아이디어, 후보 폴더 없음)
  00-질문 01-불편-한손조작 10 11 12-보조-* 20 21 22 29 30 40-최종보고서

runs/2026-10-24-discover-rear-tap-scroll/   ← /discover
  00-질문.md
  50-특허지도.md    살아 있는 벽 / 자유 실시 후보 / 풀었다·못 풀었다
  52-청구항.md      한국 특허 1항 원문·출원인·법적 상태 (KIPRIS API)
  51-제품대조.md    특허 → 제품 대조표, 빈 칸 표
  12-보조-*.md
  60-제안.md        발상 담당의 제안 3개
  29·30             출처 확인·검증
  70-제안서.md      ← 결론은 여기
```

**40-최종보고서 읽는 순서**: 한 줄 결론 → 신호등 6개(특허 여지·시장 틈·왜 지금·원가·가격·디자인 차별·**소규모 제작**) → 2절 공통 불만 3가지와 가격대 구간표 → 7절 가장 큰 위험 → 6절 가정표(우선순위 1~3번의 "가장 싼 확인 방법"과 "무엇이 나오면 접는가") → 8절 못 한 조사.

**소규모 제작 신호등 뜻**: 초록 = 금형·초기비 1,000만 원 이하, 최소 주문 1,000개 이하, 인증 KC 한 종 이하. 노랑 = 셋 중 하나 초과. 빨강 = 둘 이상 초과이거나 배터리·전파·의료기기 인증이 필요. 실용 모드에서 "특허 미조사"는 노랑이고 "사람 확인"으로 넘어갑니다. 쿠팡·아마존 숫자 옆의 "(원문 미열람)"은 검색 요약만 봤다는 뜻입니다.

**70-제안서 읽는 순서**: 특허 지도 요약(살아 있는 벽 몇 건, 자유 실시 후보 몇 건) → 제품 대조의 빈 칸 → 제안 3개(재료·베끼는 것·비켜 가는 것·틀릴 가정·확인 방법) → 총괄 순위 → "하나를 고르시면 /invent 2단계로".

**등급 뜻**: 확인됨 = 독립 출처 3개 이상 / 추정 = 1~2개 또는 범위가 다름 / 미확인 = 출처 없음 / 미확인(발상) = 발상 담당의 제안, 검증 전까지 가설.

## 8. 결과를 기계로 검사하기

프로젝트 폴더에서 치는 명령 셋입니다. 보고서를 받기 전에 돌리면 빠진 파일·상한 초과·등급 누락·죽은 링크·틀린 특허번호를 잡습니다.

규칙 검사(산출물·조사 횟수 상한·보고서 등급. /discover 폴더면 제안이 정확히 3개인지, 발상 담당이 검색을 0회 했는지도 봄):

```bash
python -I tools/완료확인.py runs/2026-10-24-discover-rear-tap-scroll
```

출처 검사(URL 열림, 특허번호↔링크 엄격 대조, 인용문↔본문. 하위 폴더까지):

```bash
python -I tools/출처확인.py runs/2026-10-23-bathroom --out runs/2026-10-23-bathroom/29-출처확인.md
```

한국 특허 청구항 원문(출원번호를 주거나 결과 파일을 가리키면 1항 원문·출원인·등록·거절·의견제출 이력·공보 PDF 경로):

```bash
python -I tools/kipris_청구항.py 1020250013141 --claims 3
python -I tools/kipris_청구항.py --from runs/<실행>/50-특허지도.md --out runs/<실행>/52-청구항.md
```

"위반 N건", "링크 없음 → 삭제 대상"이 나오면 그 줄을 총괄에게 알려 주시면 고칩니다.

## 9. 막혔을 때

| 증상 | 뜻 | 하실 일 |
|---|---|---|
| 보고서에 "(원문 미열람)" / "리뷰 출처 1곳" | 쿠팡·아마존·알리바바가 봇 차단으로 안 열려 검색 요약만 씀 | 기본 동작이라 하실 일 없음. 원문이 꼭 필요하면 "Aside 사용"을 붙여 다시 |
| "특허 미조사" / "특허 간단 확인만" | 실용 모드의 특허 상한(KIPRIS 10회)에 닿음 | 그대로 두시거나, 깊게 보려면 `/invent --특허`로 다시 |
| 소규모 제작 신호등 빨강 | 초기비·MOQ·인증 중 둘 이상이 소규모 범위를 넘음 | 보고서 7절 이유를 보고 접거나 사양을 줄여 다시 |
| ("Aside 사용" 실행만) "Aside isn't running" / "402 Insufficient credits" / 알리바바 캡차 | Aside 앱 꺼짐 / 크레딧 소진 / 봇 판정 | 재시도 없이 "Aside 막힘"으로 적히고 열리는 출처로 대신함. 앱을 켜고 로그인·충전 뒤 "다시 돌려 줘" |
| Google Patents "Sorry..." / Espacenet "잠시만 기다리십시오" | 연속 조회로 봇 판정 | 우회하지 않음. 해외 건은 "사람 확인"으로 넘어가고 한국 건은 KIPRIS 도구로 대체. 몇 시간 뒤 재시도 |
| 유튜브 "Quota exceeded" | 일일 할당량 초과 | 다음 날, 또는 그대로 두면 "0건"으로 적힘 |
| "KIPRIS MCP 미설정" / "KIPRIS_API_KEY 없음" | 키 없음 | README대로 키 등록 후 Claude Code 재시작 |
| 한국 특허 "청구항 미확인" | MCP 서지 도구가 청구항을 안 줌 | 8절의 `kipris_청구항.py`로 받으면 해결 |
| CPC 검색 "INVALID_REQUEST_PARAMETER_ERROR" | MCP의 CPC 도구 오류 | 총괄이 IPC 검색으로 대신함. 하실 일 없음 |
| "세션 한도" 오류로 멈춤 | 사용량 한도 | 한도가 풀린 뒤 "다시 열었어" |
| 담당이 "이전 세션이 끝나 완료되지 않음"으로 멈춤 | Claude Code가 닫히며 담당 중단 | "이어서 해 줘"라고 치면 그 담당을 같은 자리에서 재개 |
| 새 담당 이름이 "not found" | 담당 정의를 세션 중에 추가함 | Claude Code를 다시 열면 등록됨. 그 전엔 총괄이 범용 담당으로 대신 돌림 |
| ("Aside 사용" 실행만) 쿠팡에서 "리뷰 많은 순"이 없다고 멈춤 | 쿠팡 정렬 메뉴 차이 | 총괄이 "랭킹순 상위 10개 중 리뷰 최다"로 바꿔 재시도 |

로그인·결제·글쓰기·좋아요·문의는 어떤 사이트에서도 하지 않습니다.

## 10. 알아 두실 규칙 (요약)

- 모드: 기본은 실용 모드. `--특허`를 붙인 /invent와 /discover만 특허 모드. 모드는 `00-질문.md`에 적히고 검사기가 모드별 상한으로 봅니다.
- 조사 횟수 상한: 탐색 영역당 웹검색 10회. 심층 후보당 담당별 웹검색 20회, 보조 4회. 기존 해법의 특허는 실용 모드 KIPRIS 10회·Google Patents 5건·청구항 3건, 특허 모드 KIPRIS 20회·청구항 20건. Aside는 기본 0회, "Aside 사용" 실행만 6회. /discover 특허 지도 KIPRIS 20회 + 웹검색 20회 + 청구항 도구 60건, 제품 대조 웹검색 20회, 보조 4회, 발상 0회. 넘기라고 하시면 넘기되 `00-질문.md`에 기록하고 검사기가 "초과"로 표시합니다.
- 기존 해법 담당은 리뷰 출처 2곳 이상, 공통 불만 3가지, 가격대 구간표, 판매량 대리 지표를 반드시 냅니다. 못 열었으면 "리뷰 미열람"으로 쓰고 지어내지 않습니다.
- 구현·원가 담당은 소규모 제작 세 숫자(금형·초기비 합계 / 최소 주문량 / 인증)와 신호등을 반드시 냅니다. 빨강이면 "소규모로는 어렵다"고 그대로 씁니다.
- 특허번호는 검색 결과에서 번호와 링크가 함께 나온 것만(두 모드 공통). 번호만 적힌 것은 출처 검사가 "삭제 대상"으로 잡습니다. 실용 모드에서는 특허를 못 봤으면 "특허 미조사"라고 쓰면 됩니다.
- 발상 담당의 제안은 사실이 아닙니다. 점수표에 올리지 않고, /invent 2단계 검증을 거쳐야 등급이 올라갑니다.
- 가격·별점·통계에는 조회일이 붙습니다. 특허 상태도 조회일 기준입니다.
- KIPRIS 청구항 조회는 월 1,000회 무료 한도를 모든 실행이 나눠 씁니다.
